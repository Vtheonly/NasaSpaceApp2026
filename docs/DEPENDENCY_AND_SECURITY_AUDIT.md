This audit reflects the **actual** repository state; it is re-run whenever
`pyproject.toml` or the offline workflow changes.

## 2. Data licensing and attribution

- **FIRMS active-fire CSVs:** NASA FIRMS data are freely available; any demo or
  publication must attribute NASA FIRMS / LANCE and reference the product
  (MODIS Collection 6.x, VIIRS 375 m S-NPP). Archiving/redistribution terms
  must be checked for the specific bulk-download route before staging a
  dataset.
- **Optional HLS imagery (not implemented):** carries its own NASA/USGS terms;
  must be validated per docs/ARCHITECTURE.md Pillar 3 before any use.
- **Committed fixtures:** 100% synthetic (seed 2026, generated by
  `tests/fixtures/generate_fixtures.py`); no NASA data is committed, and all
  fixture-derived evidence is labeled SYNTHETIC (docs/MODEL_CONTRACTS.md
  section 9, assumption 5).

## 3. Secrets and credentials

- The repository **must not** contain tokens, passwords, or account data;
  `.gitignore` covers environments and common secret files.
- Push access uses short-lived personal access tokens that are entered at push
  time and **rotated immediately after use**; a token that ever appears in a
  chat log, screenshot, or terminal transcript is treated as leaked and
  revoked.
- Error messages, logs, manifests, and demo reports are audited to contain
  file paths and metrics only - never credentials (`tests/offline/` guards the
  import surface; grep CI for the `ghp_`/`github_pat_` prefixes would be added
  if a leak ever lands).
- `SECURITY.md` documents how to report vulnerabilities.

## 4. Offline behavior (verified, not assumed)

| Guard | Where it is enforced |
|---|---|
| No network imports anywhere in `src/` | `tests/offline/test_offline_safety.py` |
| Lazy, optional torch import with a clear degradation error | `src/models/patchtst.py`, `src/calendar/forecast.py::torch_available` |
| Install only from the local wheelhouse (`--no-index --find-links`) | notebook 02 |
| Wheel/checkpoint SHA-256 re-verified offline from the staging manifest | notebooks 01/02 |
| Artifact loads verify recorded model hashes (`ArtifactIntegrityError`) | `src/artifacts/serialization.py`, `tests/unit/test_artifacts.py` |
| Kaggle input read-only; outputs only under the working path | notebooks 02-06, docs/DEVELOPMENT.md |

A failed network request alone does not prove offline safety; the quarantine
notebook must complete an install, imports, and a forward pass with the
network toggle off before heavy compute is trusted.

## 5. Artifact security

- Every versioned artifact directory carries `manifest.json` with schema
  version, source hashes, code commit, config, model SHA-256, metrics, and
  limitations.
- Loading re-verifies the model hash and raises instead of silently using a
  corrupted model (tested in `tests/integration/test_roundtrips.py`).
- Quarantined rows are never dropped silently: reason codes and counts are
  written to `dataset_audit_report.json` and surface as gate failures when
  critical.
- Generated outputs (wheelhouses, weights, processed data, notebook caches)
  are excluded from Git; only small synthetic fixtures and source are tracked.

## 6. App-facing security rules (for the planned Streamlit host)

- The app reads only exported artifacts; it never retrains, never fetches
  network resources in demo mode, and labels cached/sample data distinctly.
- Errors must not echo stack traces or environment details to end users.
